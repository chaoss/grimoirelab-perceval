## perceval 1.6.0rc1 - (2026-09-16)

**Performance improvements:**

 * Conditional requests (ETag) for the GitHub backend (#915)\
   The GitHub client now stores the ETag returned for each resource and
   replays it as an If-None-Match header on the next request. Unchanged
   pull requests, issues and their sub-resources are revalidated with a
   cheap "304 Not Modified" that reuses the cached body, instead of re-
   downloading the full response on every collection run. Because a 304
   does not count against the token's primary rate limit, repeated runs
   use less rate-limit budget and bandwidth.
